## 참고한 기준과 실제 반영

- [StageVision](https://github.com/xrpjwk8/StageVision/tree/1757e0cc9cf0155a0e96b1e8e5ed1ad22c673c71): RoomCaptureView, 바닥 외곽 추출, AR 카메라 투영 기반 1m 격자를 `RoomScanner.swift`에 이식했다. 원본 전체 앱으로 저장소를 교체하지 않았다. iOS 18 호환, 취소·실패 처리, 원본 CapturedRoom 및 바닥 transform 저장, 수동 확정 단계를 추가했다.
- [WebRTCPrac](https://github.com/HyeonjinBack/WebRTCPrac): 두 기기 영상 통신 방향의 참고 자료. 오래된 의존성과 예제 화면을 그대로 가져오지 않고, 역할·세션·상태 모델을 StagePoint에 맞게 구현했다.
- [Figma 기획](https://www.figma.com/design/GfvOEZoxjcen2Bv3zHh5YU?node-id=349-2): 349:11 스캔, 349:15 범위 수정, 349:19 촬영, 349:39 운영 화면의 배치를 참고했다. 이미지형 와이어프레임이므로 픽셀 복제 대신 실제 작동하는 SwiftUI 화면으로 구현했다. iPhone 가로의 큰 영상, 작은 상태 표시, iPad의 큰 평면도와 작은 보조 영상을 유지했다. 스캔의 격자 색상은 StageVision 기준이다.
- [stasel/WebRTC](https://github.com/stasel/WebRTC/tree/153.0.0) SPM 정확한 버전 153.0.0을 사용한다. 최초 빌드 때 네트워크로 패키지와 바이너리를 내려받는다.

## 실행 준비

1. iPhone·iPad·개발용 Mac을 같은 신뢰할 수 있는 Wi-Fi에 연결한다. AP의 기기 간 통신 차단이 꺼져 있어야 한다.
2. Mac에서 아래 연결 서버를 실행한다. Node.js 20 이상이 필요하다.

```sh
cd SignalingServer
npm ci
STAGEPOINT_HOST=0.0.0.0 npm start
```

기본 실행은 localhost에만 열린다. 위 설정은 시험하는 동안 Mac의 모든 네트워크 인터페이스에서 8080 포트를 연다. 신뢰하는 사설망에서만 사용하고 시험 후 종료한다. 방화벽 허용이 필요할 수 있다. 인터넷에 노출하지 않는다.

3. `StagePoint.xcodeproj`의 `StagePoint` 스킴을 iPhone과 iPad에 각각 설치·실행한다. 하나의 스킴을 두 기기에 차례로 실행하면 된다. 실기기 서명은 본인의 Development Team을 사용한다.
4. iPhone은 **촬영 기기**, iPad는 **운영 기기**를 선택한다. 두 기기에 같은 `ws://<Mac의 LAN IP>:8080`, 세션 이름(영문·숫자·하이픈 4~32자), 임시 연결 암호(12~128자)를 입력한다. 예시 암호를 고정 공유하지 않는다.
5. 요청 시 카메라·로컬 네트워크 권한을 허용한다. 연결 완료 후 iPhone에서 **무대 스캔**을 누른다. LiDAR 및 RoomPlan 지원 여부를 앱에서 검사한다. 미지원 기기는 **무대 크기 수동 설정**으로 전송·보정 흐름을 시험한다.
6. 스캔 중 iPad에는 진행 상태가 표시된다. RoomPlan과 영상 촬영이 같은 카메라를 동시에 점유하지 않도록 WebRTC 캡처를 먼저 중지한다.
7. 스캔 완료 후 가로·세로 및 드래그 손잡이로 실제 직사각형 공연 구역을 수정한다. 필요하면 가로·세로를 바꾸고 앞쪽 방향·경계 확인을 체크해 확정한다.
8. iPhone을 삼각대 등에 고정한다. **기준점 보정**에서 A=관객 기준 앞 왼쪽, B=앞 오른쪽, C=뒤 오른쪽, D=뒤 왼쪽으로 맞춘다. 무대 뒤에 설치했다면 앞·뒤 전환 후 다시 확인한다.
9. 기준점과 다른 바닥 표식 3곳 이상을 골라 줄자로 잰 X/Y(m)를 입력하고 오차를 기록한다. 서로 떨어진 중앙·먼 곳·가장자리를 확인한다. 직접 확인 체크 후 보정을 확정한다. 현재는 허용 오차를 자동 안전 판정하지 않는다.
10. iPad 평면도를 누르면 목표 A가 iPhone으로 전달된다. 촬영 기기가 현재 세션·보정을 검증해 적용한 뒤 두 화면의 평면도/영상에 표시된다. 미응답은 3초 뒤 안내하며 자동 재전송하지 않는다.

서버 없는 화면 확인은 연결 설정의 **데모 화면**을 사용한다. 데모는 실측·실제 연결이 아님을 표시한다. 실제 스캔 완료를 가장하지 않는다.

## 구조와 데이터

- `DeviceRoleView` / `LiveWorkspaceView`: 역할 선택, 연결, 촬영, 운영 화면.
- `RoomScanner`: StageVision 기반 RoomPlan 스캔과 로컬 스캔 보관.
- `LiveRTC`: 영상 트랙 + 순서 보장 DataChannel. 카메라/RoomPlan 소유권 전환, 현재 연결 이외의 늦은 콜백 무시.
- `LiveSession`: iPhone이 무대·보정·목표 상태를 소유하며 1초마다 전체 스냅샷을 공유. iPad는 명령을 보내고 적용 응답을 기다린다.
- `StagePointCore/LiveStage`: 버전·세션·revision·좌표 범위 검사. 이전 상태 역전과 다른 세션의 상태 혼입 방지.
- `CalibrationEditor` / `CalibrationProbe`: 원근 변환, 독립 실측 오차, 로컬 검증 기록.
- `SignalingServer`: 두 역할의 입장·offer/answer/ICE 중계만 담당. 영상·무대 데이터는 서버에 저장하거나 중계하지 않는다. WebRTC 미디어와 DataChannel로 기기 간 전송한다. STUN/TURN은 아직 없다.

RoomPlan은 초기 스캔 좌표계의 치수·바닥을 제공한다. 이후 삼각대로 옮겨 고정한 카메라의 영상 좌표와 자동 정렬되지 않으므로 **별도 네 기준점 보정이 필수**다. 공연 영역은 현재 직사각형이며 네 모서리를 사용한다. 임의의 내부 기준점으로 푸는 일반 보정은 아직 없다.

영상과 오버레이는 분리한다. 원본 영상을 전송하고, 같은 정규화된 보정·목표 정보를 각 화면에서 그린다. 종횡비 맞춤 여백을 제외한 동일한 영상 영역을 투영·터치에 사용한다. 같은 화면 비율의 해상도 변경은 정규화 좌표를 유지한다. 화면 비율 변화는 보정을 무효화한다. 프레임과 명령의 엄밀한 시간 동기화는 구현하지 않았으므로 동적 사람 추적에 그대로 쓰면 안 된다.

앱이 백그라운드로 가거나 연결이 끊기면 목표·보정을 해제한다. 3초 이상 영상/상태가 갱신되지 않으면 운영 화면의 위치 입력을 막고 중단 표시를 한다. 재연결 뒤 실제 카메라 위치를 확인하고 재보정해야 한다. 카메라의 물리적 움직임을 자동 감지하지는 않으므로 움직인 경우 **카메라 이동됨**을 눌러야 한다.

로컬 저장 위치는 앱 Application Support의 `StagePointLive/`다.

- `latest-scan.json`: 최신 스캔 하나. CapturedRoom 원본·바닥 외곽·transform·측정 시각. 다시 불러와도 사용자 확정이 필요하다.
- `calibrations/<ID>.json`: 치수·네 기준점·독립 검증 오차·날짜·데모 여부. 다음 실행에 보정을 자동 재사용하지 않는다.
- 영상·음성은 녹화하지 않고, 마이크 트랙도 만들지 않는다. 연결 암호는 저장하지 않는다. 서버 주소만 설정에 보관한다.

WS 연결 암호는 TLS로 보호되지 않으므로 현재 연결 서버는 사설 시험망 전용이다. 외부 운영에는 WSS, 인증·기기 신뢰 설정, TURN, 장애 복구, 보안 검토가 추가로 필요하다. 비콘과 착용 기기만으로 무용수의 정확한 좌표를 안다고 가정하지 않는다.

- iPhone 17 Pro + iPad Pro 13-inch (M5) 시뮬레이터: 합성 프레임을 실제 WebRTC 경로로 인코딩·전송·수신, 무대 정보 공유, 목표 A 명령 및 응답 확인. 상대 종료 시 영상/보정/목표 해제, 재입장 후 새 연결과 목표 전달을 확인했다. 실제 카메라 또는 서로 다른 물리 기기에서의 시험은 아니다.
- 직접 앱 설치·실행 중 WebRTC 런타임 로딩 경로를 수정했다. 전송 중 같은 종횡비로 해상도가 바뀌는 경우의 불필요한 보정 해제도 수정했다.

재현 명령:

```sh
swift test --package-path Packages/StagePointCore
cd SignalingServer && npm test
# 저장소 루트에서 실행
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild \
  -project StagePoint.xcodeproj -scheme StagePoint \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  CODE_SIGNING_ALLOWED=NO test
```

UI 테스트는 `--uitesting --live-demo`로 데모 화면에 진입한다. 전송 시험은 **Debug + Simulator에서만** `--transport-camera`, `--transport-monitor` 인수를 지원한다. 이 시험은 localhost:18080 서버, `sim-transport` 세션, 시험용 고정 토큰을 사용하며 합성 영상과 보정 데이터를 주입한다. 실제 기기 및 Release에서는 인수를 무시한다. 전송 시험의 자동 보정은 정상 앱의 사람이 확인하는 과정을 대체하지 않는다.
